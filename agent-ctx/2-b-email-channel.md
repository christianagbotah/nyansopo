# Task 2-b (Wave 12 / Backlog D) — Email Channel (CI3 `Invoice_email.php` + `Email_model.php` parity)

## What was built

### 1. lib — `src/lib/email.ts` (new)
Mirrors the shape of `src/lib/sms.ts` + `src/lib/sms-gateway.ts`:

- `getEmailTransport(setting)` — lazy **pooled** nodemailer transporter per school, only when `setting?.enabled && setting.host`; cached in a module-level Map keyed by schoolId with an in-memory settings signature so a settings change swaps (and closes) the transporter.
- `sendEmail({ db, schoolId, to, toName?, subject, html, category, sentByName?, studentId? })` — lowercases + regex-validates `to` (invalid → FAILED row "Invalid email address"); loads EmailSetting; configured+enabled → real `transport.sendMail` with `from: { name: fromName, address: fromAddress || username || "noreply@nyansapo.app" }` → SENT row, on throw → FAILED row with `errorReason: e.message`; NOT configured/enabled → **SIMULATED** row (SMS-gateway no-key philosophy: log the intent, never block the workflow). Throws never; returns the created EmailMessage row.
- `invoiceEmailHtml({ school, invoice, student, term, items })` — inline-styled HTML email, Nyansapo-green palette, no external images, **every** interpolated string HTML-escaped (`esc` helper): school letterhead (name + town + "Ghana"), invoice no / issued / due date, learner + class + term, line-items table, totals block (gross, discount when >0, paid-to-date, bold **Outstanding**), MoMo hint (`Pay via MTN MoMo to {school.phone} — quote invoice …`, office fallback when no phone), footer "…generated by {school}. Powered by Nyansapo." GH₵ via `en-GH` formatting.
- `testEmailHtml(schoolName)` — short body for test-send.
- nodemailer 10.4 ships its own ESM types (`dist/esm/nodemailer.d.ts`, default export) — `@types/nodemailer` is unused by the main import; `import nodemailer, { type Transporter } from "nodemailer"` works with `moduleResolution: bundler`.

### 2. API — `src/app/api/school/[id]/ops/email/route.ts` (new, sms-route pattern)
- **GET** (`perms: ["email.send"]`, `strict: true` — teacher/association view get 403): `setting` (**never the password** — `hasPassword: boolean` + enabled/host/port/secure/username/fromName/fromAddress), last 60 `messages` (id, toAddress, toName, subject, category, status, errorReason, sentByName, sentAt — NOT body), `stats` (total/sent/failed/simulated), `invoiceCounts` (current-term invoices with / without guardian email), `termName`.
- **POST** (`perms: ["email.send"]`) actions:
  - `save-settings` — host required when `enabled` (400), port integer 1–65535 (400; blank → 587), **blank/omitted password keeps the stored one** (sms pattern); upserts EmailSetting; response repeats the safe field set only.
  - `test-send` — `{ to? }` defaults to the sender's own `user.email`; subject "Nyansapo email channel test", category TEST; returns the message row (status tells SENT/SIMULATED/FAILED).
  - `send-invoice` — `{ invoiceId }` (required 400; wrong school → 404); 400 **"This learner's guardian has no email address on file"** when `student.guardianEmail` is null; classroom falls back invoice.classroomName → active enrollment; renders invoiceEmailHtml; category INVOICE, `toName` = guardian name, `studentId` set.
  - `bulk-send-invoices` — `{ scope: "ALL" | "UNPAID" | "CLASS:<classroomId>" }` (else 400); no current term → 400; UNPAID = outstanding > 0; CLASS = learner actively enrolled in that classroom; **> 200 targets → 400**; skips guardians without email (`skipped`), returns `{ sent (SENT+SIMULATED), skipped, failed }`.
- Subjects mirror CI3: `Invoice {invoiceNo} — {school name}`.

## Key facts for later agents
- **SIMULATED is the default**: no EmailSetting row / disabled channel → every send (test, invoice, bulk) logs status SIMULATED and returns 200. Don't "fix" that — it's the offline-first parity decision.
- The SMTP password lives ONLY in `EmailSetting.password`; it is never returned by GET/save-settings, never logged, and the transporter cache signature stays in memory. GET exposes just `hasPassword`.
- `sendEmail` **never throws** — check `row.status` on the returned row ("SENT" | "FAILED" | "SIMULATED") instead of catching.
- Deep-link `pg-email` (perm `email.send`) already existed in page-index.ts — nothing had to change there.
- invoice classroom resolution: `invoice.classroomName` (denormalised at billing) → active enrollment fallback; both are escaped in the HTML.
- Did NOT touch: `prisma/schema.prisma` (EmailSetting/EmailMessage already existed), `src/lib/rbac.ts` (`email.send` already existed), `src/components/app-shell.tsx`, `src/lib/page-index.ts`, `src/lib/store.ts`, `src/app/page.tsx`, `src/components/modules/settings.tsx`, `src/app/api/school/[id]/ops/backup/**` (task 2-a owns those).
